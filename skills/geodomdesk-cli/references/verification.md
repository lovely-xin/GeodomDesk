# 实测方法

## 验收条件

需要挑选实测目标时，先从「最近访问」列表选择已授权设备，确认在线状态、目标身份和所需能力。离线或能力不匹配时，换用列表中符合条件的在线设备。通过一条最小只读命令或已知服务的实际握手完成验证。用户指定设备时，按指定目标核对在线状态。

记录发起端 CLI 版本和支持的参数，再按目标设备实际可用的服务与权限选择检查。用已授权设备、已知端口和只读命令。临时映射记录本次 UUID，测试结束核对清理。

| 场景 | 通过条件 |
| --- | --- |
| Linux Bash 经 TCP 隧道 | 用已支持的内置 SSH 或显式隧道运行只读脚本，核对实际通道、退出码及输出。支持时用 `command_transport: ssh-relay` 确认内置 SSH。 |
| Windows PowerShell 经 TCP 隧道 | 按所选 SSH 或 WinRM 路径验证服务身份和认证。运行只读命令核对目标 Windows 与实际输出，释放远程会话并验证隧道关闭。 |
| Windows 终端中继 | 支持时用 `--transport terminal --relay` 运行只读脚本，核对目标身份、`command_transport: terminal`、结果和输出完整性。旧协议的大输出可用可预测内容与字节数验证。 |
| 会话管理 | 按当前协议核对连接复用。支持 `fresh` 时，检查该请求使用新连接。支持取消时，核对中断状态和下一条新请求的恢复。 |
| 独立 CLI 登录和取消 | 用独立进程核对登录复用。用隔离账号注销后，现有 SSH 和终端会话的下一条命令应在执行前被拒绝。核对凭据输入时无隧道，取消建连时本次 UUID 立即移除。 |
| TCP 隧道 | 等 `tunnel_ready`，向本地端口发送已知服务请求，核对 `active_connections`、端口和 UUID。收到关闭确认后，核对数据连接结束、监听端口可重新绑定，且列表找不到测试 UUID。测试逐连接账号校验时，使用隔离账号确认已有映射在注销后拒绝新数据连接。需要检验异常退出时，只停止本轮启动的测试所有者，再对同一 UUID 调用 `close`，核对 `already_closed` 和记录清理。 |
| 内置 SSH 和远端设备中转 | 核对中转设备身份、最终服务主机密钥、`ssh_destination` 和只读响应。会话中核对同一连接 ID 的复用及新连接 ID 的重建。确认 `private_stream: true` 的隧道在关闭后从列表移除。 |
| 图形客户端 | 只有任务要求验证界面显示或点击时才使用电脑操作。先由 CLI 建立测试映射，再在同系统、用户、配置目录下打开该设备的 TCP 隧道页。核对 CLI 行与实际状态，点关闭本轮 UUID 对应的行，随后用 CLI 核对进程、数据通道和记录。已有手工映射及其他 CLI 行应保留。 |

只读 `probe` 用来确认通道能力，实际命令或服务握手用来确认功能。CLI `tunnel list` 与 GUI 测试分别记录，只有界面实际打开并完成操作才算通过图形流程。

需要比较稳定性时，在同一发起端和目标上使用相同的只读任务，分别核对建连成功、输出完整、断线恢复及清理。记录所用通道和失败阶段。

## 记录结果

记录发起端版本、目标平台、实际通道、测试结果和清理状态。遇到阻塞时写明发生阶段与继续所需条件。分享测试记录前移除凭据和隧道控制令牌。
